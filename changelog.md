# Changelog

## 2026-08-04

- [Changed] The "Face to Face" store button now opens the search pre-filtered to in-stock listings and sorted price low→high (`sort_by=price_asc`, `filter__Availability=In+Stock` — param names captured from the live site's sort dropdown and the In Stock filter).
- [Changed] The Vault color-identity filter now defaults to `≥ at least` instead of `≤ at most` — selecting colors without touching the operator shows cards that contain all the checked colors (e.g. checking G+W shows GW and GWU cards, not mono-white/colorless).
- [Changed] Full Art tiles now open a view-only card detail page (`/full-art/<scryfall-id>/`) instead of jumping straight into the Add-card flow — same layout as the Vault card page (art with flip, USD/CAD prices, store links) minus the vault-only Tags/Commanders/Notes sections. The printing is fetched live from Scryfall and wrapped in an unsaved `Card` instance so the model's display properties work in the template, and nothing is ever written to the database; an "Add to Vault" button in the top-right hands off to the existing Add-card flow with that exact printing pre-selected.
- [Changed] Full Art tiles now always show the price. It gets its own right-aligned slot on the name row (an em-dash when Scryfall has no USD price) — previously it was tucked at the end of a single truncating caption line, so any card with a long set name had the price cut off.
- [Added] "Hide unpriced" checkbox on the Full Art page, dropping cards Scryfall has no USD price for (unreleased sets especially, which otherwise dominate the newest-first first page). Ticking it appends `usd>0` to the Scryfall query (new `exclude_unpriced` flag on `search_full_art`) and, like "Hide lands", the choice is preserved across search, sort/set changes, and pagination. Tiles now also fall back to the foil price when a printing has no nonfoil price — foil-only printings match `usd>0` on their foil price, so they were showing an em-dash despite being priced.
- [Added] "Hide lands" checkbox on the Full Art page, so full-art basics stop flooding the gallery. Ticking it appends `-t:land` to the Scryfall query (new `exclude_lands` flag on `search_full_art`) and the choice is preserved across search, sort/set changes, and pagination.

## 2026-08-03

- [Added] Full Art gallery page (`/full-art/`, "Full Art" in the nav) for browsing full-art printings live from Scryfall — no local storage, since the Card table keeps one printing per name and has no full-art/release-date/EDHREC columns. Sort by release date, price, or EDHREC rank; filter by set (list cached for a day); search by name, with a "no full-art version of X" empty state for cards that were never printed full-art. Paginates through Scryfall's 175-per-page results preserving the active sort/set/search, double-faced cards keep their flip button, and clicking a tile opens the existing Add-card flow with that exact printing pre-selected. A Scryfall outage degrades to an error banner instead of a 500. Built on new `search_full_art`/`extract_gallery_fields`/`list_sets` helpers (`unique=prints`) — the existing `search_cards` used by the add flow and commander combobox is untouched.
- [Fixed] The "Face to Face" store button on card pages led to an empty "Search for Search" page. Face to Face Games migrated to a new Shopify storefront that ignores the old `/search/?keyword=` URL format; the link now uses the new `facetofacegames.com/search?q=` format so it lands on actual search results for the card.

## 2026-07-21

- [Fixed] Page becoming unresponsive after a drag-and-drop: navigating synchronously inside the `drop` handler tore the page down before the browser finished ending the drag, which could leave the next page stuck in a phantom-drag state (dimmed overlay, drops/clicks ignored). The add-page redirect and the commander suggest-form submit are now deferred out of the drop event (`setTimeout 0`), and a `dragend` listener resets the overlay if a drag is canceled (Esc), where `dragleave` doesn't always fire.
- [Added] Dropping a card onto a commander's page now auto-suggests it for that commander: the drop appends the commander to the card's "Good for commanders" list (append, not replace — existing commanders are kept) and the card appears in the page's "Suggested cards" grid on reload. The drag overlay reads "Drop card to suggest for {commander}" there. Unknown cards are fetched from Scryfall and stored as reference rows (like commanders); drops on every other page still route to the Add-card screen. Implemented as a hidden opt-in `#drop-suggest-form` the global drop handler POSTs to (`/commanders/<pk>/suggest/`, new `CommanderSuggestCardView` reusing `resolve_commanders`).

## 2026-07-20

- [Added] Drag-and-drop add: drag a card image from scryfall.com (another tab) and drop it anywhere on the site to jump straight to the Add-card screen with that card pre-selected and ready to submit. A "Drop card to add to Vault" overlay appears while dragging. The card's Scryfall UUID is parsed from the image URL (any size, front or back face); the add view resolves it server-side (`?scryfall=<uuid>`), reusing the search endpoint's Vault enrichment via a shared `vault_enriched_results` helper, so an already-collected card preloads its tags/commanders/notes and offers "Update in Vault". Bad or unknown drops degrade to the normal add page with a message banner. (Scryfall card-page *links* contain no UUID and are not supported yet.) File drops and text selections are never hijacked.

## 2026-07-01

- [Added] Re-adding a card already in the Vault now preloads its saved tags, commanders, and notes into the Add form when you select it (the search API cross-references results against the Vault by name). Editing and submitting updates the existing card instead of blanking it — tags/commanders now use `.set()` so removals persist — and the action button reads "Update in Vault". A confirmation modal appears only when you actually changed a tag, commander, or the notes.
- [Changed] The card page's "Remove from Vault" action is now a red button in the top-right of the card header (was a text link at the bottom), and it opens a styled confirmation modal instead of the browser's native `confirm()` dialog.
- [Added] Flip button on double-faced cards (transform, modal DFC, etc.) to view the back face. The Scryfall parser now captures the back-face image and `layout` (new `Card.image_uri_back` / `Card.layout` fields, added to `SCRYFALL_FIELDS` so `sync_prices` backfills them); a shared `_card_art.html` partial renders a ⟳ overlay button when a card `is_double_faced`, and one delegated handler in the base template swaps the art. Available in the Vault grid, card detail, add-card search results, and commander/deck views.

## 2026-06-30

- [Changed] Vault card tiles now cap their tag chips to ~2 rows; when a card has more tags than fit, the overflow is trimmed and a "…" chip is appended so it's clear there are more (keeps tiles uniform instead of growing tall with many tags).
- [Added] Vault name search: a search box in the Vault header (top-right, next to "The Vault (N)") filters cards by name (`?q=`, case-insensitive, server-side so it spans pages) and preserves the active filters/sort. Also added tag search boxes in the Vault tag filter and on the Tags page, and hid the scrollbar on the filter's tag list.
- [Added] PWA support so the site can be installed as an app (Android/Chromium, iOS, desktop): a web manifest (`static/manifest.webmanifest`), 192/512 PNG app icons, a root-scope service worker (`/sw.js`, served via a TemplateView) with an app-shell cache, and the manifest/theme-color/apple-touch-icon tags in the base template. `CSRF_TRUSTED_ORIGINS` now also reads `EXTRA_TRUSTED_ORIGINS` (comma-separated) so a tunnel/LAN origin can be trusted for POSTs. Install requires a secure origin (HTTPS or localhost).
- [Changed] Made the whole site mobile-friendly. The top nav collapses into a hamburger menu on phones (horizontal bar on desktop); the Vault filters collapse behind a "Filters & sort" toggle on mobile (sidebar on desktop); card images are capped/centered instead of full-bleed on small screens; deck-row owned/commander controls are now comfortable tap targets and the commander ⭐ is always visible on touch; plus 16px form fonts on mobile (prevents iOS focus-zoom) and an overflow-x guard. Verified across all pages at 390px with no horizontal overflow.
- [Added] Site favicon — a themed SVG (`static/favicon.svg`, indigo cards) linked from the base template; added `STATICFILES_DIRS` so it's served in dev and collected for production.
- [Fixed] White corners on card art. Scryfall's JPG card images have white corners outside the printed rounded border; card images now get a `.card-img` rounding (`border-radius: 4.75%/3.4%`) so those corners clip to the dark background. Applied to all full-card art (vault grid, card detail, commander tiles/pages, add-card search results, deck commander).
- [Changed] The "Good for commanders" section on the card page now shows each suggested commander as its full card image (a small grid of card art linking to the commander's page) instead of a text chip. The + editor is unchanged.

## 2026-06-29

- [Added] Tags now get a random color. New tags created via the card-add or card-detail tag combobox are assigned a random color from a 64-color palette, and all existing tags were backfilled with random colors. The tag edit page now offers an 8×8 grid of swatches to pick from. `Tag.color` is now stored as a hex value and chips render via inline styles (translucent fill + colored text/border), so any of the 64 colors works.
- [Added] Suggested commanders are now editable on the card page: a **+** button reveals the commander combobox (pre-seeded with the card's current commanders) where you can remove (×) or search Scryfall to add new ones, then Save. Reuses the shared commander combobox + `resolve_commanders`; an empty save clears them.
- [Added] Commanders are now a first-class space with their own pages. When adding a card you can mark which commanders it's "good for" via a type-ahead multi-select that defaults to your existing commanders (deck commanders + ones you've added) and searches Scryfall (legendary creatures only) to add new ones. Each commander has a page (`/commanders/<id>/`) showing its art/info and a grid of cards suggested for it, plus a Commanders nav section. Modeled as a self-referential `Card.suggested_commanders` M2M; `Card.objects.commanders()` unifies deck commanders and suggested-as-commander cards.
- [Added] Per-card notes: a notes field when adding a card, shown read-only on the card page until you click a pen icon to unlock editing and Save.
- [Fixed] The Scryfall Tagger link on the card page now uses Tagger's real URL format — lowercase set code + collector number (e.g. `…/card/blc/14`) — instead of a set-code + name-slug URL that 404'd. Added a `collector_number` field to Card (captured from Scryfall, refreshed by `sync_prices`); cards without a stored collector number fall back to Tagger search. Backfilled existing cards via a bulk sync.
- [Changed] The card detail page tag editor now uses the same modern type-ahead chip combobox as the add page (current tags pre-seeded as removable chips; type to search, Enter/click to add, “Create …” for new tags, Save persists). The combobox is now a shared `_tag_combobox.html` partial used by both pages, and the old multiselect + `CardTagsForm` were removed. Verified with Playwright.
- [Changed] Vault color-filter toggles are now tinted per mana color even when unselected (so each WUBRG button is distinguishable at a glance), and the Black toggle fills a true near-black when selected instead of a washed-out grey.
- [Fixed] Clicking a tag suggestion in the add-card combobox now adds it as a chip (previously only keyboard Enter worked — the hover handler was rebuilding the dropdown and eating the click). Highlighting now moves without rebuilding the list. Also wrapped the add in a transaction and confirmed new tags are only created when the card is actually added to the Vault — typing a new tag and leaving without submitting no longer leaves an orphan tag. Verified with Playwright (click path) and regression tests.
- [Changed] The add-card tags field is now a modern type-ahead combobox: typing filters existing tags in a dropdown, Enter/click appends the tag as a removable chip, and a “Create …” row lets you add a brand-new tag. Chips are removable (× or Backspace). Frontend-only (vanilla JS); the server still receives the same comma-separated `tags` value. Verified end-to-end with Playwright.
- [Added] Tags can be applied while adding a card to the Vault: a comma-separated tags field on the add confirm bar (with autocomplete of existing tags). Names that don't exist yet are created automatically; existing ones are reused (matched by slug). The create-or-reuse logic now lives in `Tag.objects.get_or_create_from_csv` and is shared with the card detail tag editor.
- [Changed] Vault tag filter is now multi-select with an Any/All match toggle — check several tags and show cards matching ANY (OR, default) or ALL (AND) of them. Logic in `CardQuerySet.by_tags`, covered by tests. Replaces the single-select tag dropdown.
- [Changed] Vault color-filter toggles now light up in their own mana color when selected (W cream, U blue, B dark, R red, G green) instead of a uniform highlight.
- [Changed] Vault color filter is now multi-select with MTG set-comparison operators. Check any of W/U/B/R/G and pick `=`, `≤`, `<`, `≥`, or `>` against a card's **color identity**: e.g. `≤ GW` returns green, white, green-white, and colorless cards. Subset operators include colorless; `=` with no colors checked shows colorless only. Filters now also persist across pagination. Logic lives in `CardQuerySet.by_color_identity` and is covered by tests.
- [Fixed] Vault card tiles with tags rendered broken — the name/price/tag floated to the right of the art instead of inside the tile. Cause was a tag-chip `<a>` nested inside the tile's card `<a>` (invalid HTML, which the browser reparents). The tile is now a `<div>` with the art/title as the card link and the tag chips as a sibling block.
- [Changed] "Add a card" is now a search-and-select flow: type a name and press Enter to see a scrollable grid of every matching card in **full card art** (Scryfall `/cards/search`, one per unique card), click a card to select it, then confirm with a **+ Add to Vault** button that lands on the card's detail page. Replaces the old type-and-instantly-fuzzy-add behavior. Backed by a JSON search endpoint (`/cards/search.json`) and an add-by-Scryfall-id confirm; covered by tests.

- [Added] The Vault: browse collected cards in a responsive grid with filtering (tag, set, type, color, rarity) and sorting (recently-added default, price, name).
- [Added] Card detail page with USD + computed CAD pricing, tag editor, and four external links (Scryfall, Tagger, 401 Games, Face to Face).
- [Added] Add-to-Vault flow backed by live Scryfall lookup (exact + typo-tolerant fuzzy).
- [Added] Tag management (create/edit/delete) and per-card tagging.
- [Added] Deck builder: list/detail with cards grouped by type (commander pinned on top) or by custom per-deck category, an owned/needed summary with cost-to-finish in USD/CAD, and a per-card "owned" toggle.
- [Added] Manual commander designation ("Set as commander").
- [Added] Decklist import (parses quantity, strips set codes/collector numbers/foil markers, skips headers/comments) — good lines import while failures and fuzzy substitutions are reported; deck-imported cards never enter the Vault.
- [Added] Bulk-edit decklist (text round-trip) that replaces deck contents while preserving `is_owned`/`category` for surviving cards, and clears a removed commander.
- [Added] Plain-text deck export for Moxfield/Arena.
- [Added] `sync_prices` management command: downloads the Scryfall "Oracle Cards" bulk file and refreshes prices/data for tracked cards without wiping tags or Vault membership.
- [Added] Tests for the decklist importer, the `sync_prices` command, and card model logic (type bucketing, CAD conversion, external links).
